# 设计文档：分类浏览抽屉交互 + 特征保留短标题（2026-11-10）

## 背景与决策

用户已定案：**A6 + A7 双轨**（Notion 分类聚合子页 + 本地手风琴，各自独立可用）+ **T1 短标题**（LLM 生成）。本轮三项新增需求：

1. 行点击 → 右侧抽屉：展示 分类/标签/抖音链接/概述/Notion 文档跳转按钮/关闭按钮；点击其他视频行自动切换抽屉内容。
2. 短标题核心思想：**最大限度保留原标题中的特征字段**（专有名词、数字、核心概念），防止 LLM 整理后标题同质化、失去区分度。
3. 两轨各自独立完成浏览闭环。

## 功能 1：视频详情抽屉

### A7（本地手风琴，`/demo/cat-accordion`）

- 行为：点击视频行（整行可点）→ 右侧滑出抽屉；点击其他行 → 抽屉内容原位切换（不关闭重开）；✕ 按钮或 ESC 关闭。
- 抽屉内容（自上而下）：
  1. 短标题（主标题）+ 原标题（次级灰色展示）
  2. 分类 › 细类（chips）
  3. 标签（chips）
  4. 「▶ 抖音视频来源」外链
  5. 视频概述（精华版全文摘要，可滚动）
  6. 主按钮「打开 Notion 总结文档 ↗」（`notion_url`，无则回退 `source_url`）
- 数据源：`/demo/api` 索引（aweme_id 定位）。

### A6（Notion 分类聚合子页）

Notion 无法自定义抽屉组件，用**原生侧边 peek** 承载同等信息：点击行 → Notion 右侧 peek 打开行页面，内含：

- properties：短标题（Name）/ 分类 / 细类 / 标签 / 概述 / 视频来源（URL，即抖音链接）/ 原标题 / 视频ID
- 页面 body 顶部已有 📌 概述 callout + 笔记全文
- 分类子页内嵌 filtered list 视图不变（每行点击即 peek）

## 功能 2：特征保留短标题（T1 v2）

- Prompt 升级：明确要求保留原标题中的**专有名词（产品/模型/公司/课程名）、数字、核心技术概念**；标题需能与库内其他视频区分；仍 ≤18 字、去 #话题/@用户/钩子语。
- 同名去重：`make_unique` 对重复短标题追加（2）/（3）后缀（允许超上限 ≤3 字，保特征优先于字数）。
- 落库（39 篇回填 + 未来增量）：
  - database 新增 property：`原标题`（rich_text）、`视频ID`（rich_text，= aweme_id，作为行的稳定主键）
  - Name → 短标题（去重后）；原标题/视频ID 回填
  - 后续脚本一律按 视频ID 定位行（不再依赖标题匹配，重命名不破坏幂等）
- 笔记 frontmatter 不动（本地 Markdown 保持原标题）。

## 约束

- MVP 路径零改动；所有写入失败降级不影响主流程（沿用现有机制）
- Notion 连接器（MCP）本轮不可用也无妨：全部落库走 REST + ntn_ token
- 短标题 v2 prompt 与去重逻辑进 `short_title.py`，pipeline 集成（新视频自动全流程）为下一阶段
