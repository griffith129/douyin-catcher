# Agent 的 Todo List 有什么用？ 三分钟带你搞懂，大模型明明自己会做推理规划，为什么各大 Agent 还要专门给它配一个 Todo List 工具呢？#vibe知识大赏 #抖音前沿科技首发计划 #AI新星计划 #大模型 #王二讲Agent

## 精华版

> 快速上手：大模型与 Agent（智能体）
> - **一句话本质**：大模型根据输入生成输出；Agent 是让大模型调用工具、分步完成任务的系统。
> - **结构化拆解**：大模型负责理解与生成；Agent 由模型、工具、任务循环、结果记录组成，模型读指令、调用工具、读结果、继续下一步。
> - **作用定位**：本文讨论 Agent 为何需要任务清单，理解这两个词后才能看懂清单如何影响执行。

> 快速上手：Todo List（任务清单）
> - **一句话本质**：Todo List 是把待办任务及状态列成清单的结构化记录。
> - **结构化拆解**：由任务描述与状态组成；机制是拆分目标、记录进度、反复更新；本文中状态有待处理、进行中、已完成。
> - **作用定位**：它既是模型执行控制工具，也是用户观察和纠正 Agent 的界面。

视频结论：任务清单不是给用户看的进度条，而是 Agent 的执行控制工具。它把大目标拆成具体步骤，并通过反复重写清单，把目标和进度重新带回近期对话信息，减少长任务跑偏；同时把进度展示给用户，便于在跑偏前纠正。具体实现上，视频以某编程智能体工具为例：只暴露一个覆写工具，每次用完整数组覆盖整张清单，任务项只有描述和状态，状态只有待处理、进行中、已完成。约束上，提示词加代码校验：复杂多步任务先列清单，完成一项立即标记；配置开关为 false 时只允许一个进行中，并拦截空白/重复描述。展示上，模型消息与前端面板分离：工具只给模型返回统计文本，完整参数进入对话记录，同时追加事件供界面状态更新；新提问触发开始事件时清空旧面板，不删除历史事件。长对话压缩时用固定摘要格式把未完成任务写入待办和当前工作章节，但依赖摘要质量，不能保证绝不丢失。边界上，只做规划的模式应把清单用于跟踪方案获批后的执行进度，且工具仍可调用、不是代码权限隔离；多个智能体各管各的清单可完整覆盖，共同维护一张清单时按编号更新并配合任务先后关系更合适。

## 整体逻辑链条梳理

1. **问题起点**：大模型会推理规划，但长任务中工具结果越来越多，最初目标容易被淹没 → 需要外部任务清单。衔接：清单如何真正影响模型执行？
2. **实现机制**：每次提交完整清单，把目标与进度重新带回近期对话信息，减少目标偏移。衔接：但清单状态必须可信，否则模型会乱标状态。
3. **状态约束**：用提示词规定使用时机，用代码校验限制同时进行中的任务数量，并拦截空白、重复描述。衔接：模型和界面如何同时拿到清单？
4. **展示与持久**：模型消息、事件日志、界面投影分离；长对话压缩时用固定摘要格式保留未完成任务。衔接：不同场景能否照搬？
5. **场景边界**：规划阶段与执行进度要区分；多个智能体各自维护清单可完整覆盖，共享任务板更适合按编号更新并配合依赖关系。

## 一句话结论

对应逻辑链：全链条收束。Todo List 在 Agent 中不是进度条装饰，而是通过拆分目标、全量重写清单把目标与进度带回近期对话信息、约束任务状态并让用户及时纠偏的执行控制工具。

## 核心要点

对应链条第 1-5 环。

1. 大模型会推理规划，但长任务中工具结果会淹没最初目标，任务清单用拆分步骤和反复重写清单对抗目标漂移。
2. 视频中的实现只暴露一个覆写工具，每次用完整数组覆盖整张清单，任务项仅含描述与状态，状态只有待处理、进行中、已完成。
3. 防止任务被随意标为进行中靠提示词加代码校验：配置为 false 时只允许一个进行中，并拦截空白和重复描述。
4. 模型消息与前端状态分离：工具只给模型返回统计文本，完整参数进入对话记录，同时追加事件供界面状态更新，新一轮提问清空旧面板但不删历史事件。
5. 长对话压缩用固定摘要格式把未完成任务写入待办和当前工作章节，但依赖摘要质量，不能保证任务绝不丢失。
6. 只做规划的模式应把清单用于跟踪方案获批后的执行进度；多个智能体各管各的清单可完整覆盖，共同维护一张清单时按编号更新并配合任务先后关系更合适。

## 关键细节

对应链条第 2-5 环。

- 视频以 DeepSeek Harness 与 Claude Code 的输入框上方任务面板为例：面板显示“2 已完成、1 进行中、3 待处理”，展开后是带状态圆点的任务清单。

> 快速上手：DeepSeek Harness / Claude Code
> - **一句话本质**：它们都是面向编程任务的 Agent 工具，用对话方式调用工具完成代码相关任务。
> - **结构化拆解**：由对话入口、执行外部动作的模块、任务面板等组成；模型接收指令后调用工具，工具结果回到对话，界面根据记录更新状态。
> - **作用定位**：本文用它们说明 Agent 为什么需要任务清单，以及清单如何被模型调用和界面展示。

- DeepSeek Harness 的 Todo 工具模块只向模型暴露一个 TodoWrite 工具；参数是名为 Todo 的数组，每项仅保留两个必填字段：Content 表示任务描述，status 表示状态；状态枚举只有 Pending、InProgress、Completed。若多传 ID 或 Priority，参数校验器会报错拦截。

> 快速上手：TodoWrite / Todo 数组 / 参数校验器
> - **一句话本质**：TodoWrite 是让模型提交整张任务清单的工具；Todo 数组是清单的数据格式；参数校验器是检查调用参数是否合规的代码。
> - **结构化拆解**：TodoWrite 只有一组参数 Todo；Todo 数组每项含 Content 和 status；状态枚举限定三个值；校验器检查必填字段和多余字段，不合规就报错。
> - **作用定位**：它让清单更新变成一次结构化写入，避免模型记忆任务编号，也保证状态值可控。

- 视频解释全量覆写原因：省去模型跨轮次记忆任务编号的负担；并引用 Manus 团队博客 Context Engineering for AI Agents，指出通过复述把目标重新带到近期对话信息，减少长任务目标偏移。

> 快速上手：全量覆写 / Manus 团队博客 Context Engineering for AI Agents
> - **一句话本质**：全量覆写是每次提交完整清单而不是只改某一项；该博客是 Manus 团队讨论如何组织模型近期对话信息的文章。
> - **结构化拆解**：全量覆写让模型每轮重新看到全部任务与状态；博客观点强调通过复述目标把目标带回近期对话信息，减少长任务偏移。
> - **作用定位**：解释为什么视频中的工具不提供增删改查四件套，而采用单一覆写工具。

- 提示词规定：简单单步任务直接跳过，复杂多步任务在动手前先列清单；每完成一项必须立刻标 Completed，不允许累积到最后批量提交。

> 快速上手：提示词
> - **一句话本质**：提示词是给模型的指令文本，用来规定它该怎么做事。
> - **结构化拆解**：由任务规则、输出要求、约束条件等组成；模型生成时参考这些文本；本文用它约束清单使用时机和完成标记。
> - **作用定位**：它是第一层行为约束，但单靠提示词不够，所以还要代码校验。

- 布尔配置项 allowParallelInProgress 控制是否允许多项任务同时处于进行中；设为 false 时工具描述要求同一时间只保持一个 InProgress，若提交两个以上 InProgress，工具执行模块里的校验函数会抛异常并返回错误结果，让模型修正参数后重调；校验还拦截空白和重复任务描述；设为 true 可跟踪并行派发的 Sub-Agent 或后台任务，但开关只约束清单状态，不启动并发任务。

> 快速上手：allowParallelInProgress / Sub-Agent
> - **一句话本质**：allowParallelInProgress 是控制清单里能否同时有多个“进行中”任务的开关；Sub-Agent 是由主 Agent 派生出来执行子任务的智能体。
> - **结构化拆解**：开关为 false 时，提示词要求单一进行中，代码校验拦截多个 InProgress；为 true 时允许标记多项进行中；它只改清单状态，不负责实际并发调度。Sub-Agent 各自有任务，可与后台任务一起被跟踪。
> - **作用定位**：说明清单状态约束既靠提示词也靠代码，并区分“标记并行”与“真正并发执行”。

- 模型调用一次 TodoWrite 后，只给模型返回一行技术文本，告诉它当前有几项待处理、几项进行中、几项已完成；但模型发出的工具调用参数里仍包含完整清单，这部分会记录到上下文。

> 快速上手：上下文
> - **一句话本质**：上下文是模型在当前轮生成时能看到的对话与工具结果等信息。
> - **结构化拆解**：包括历史消息、工具调用参数与结果等；容量有限，长对话信息过多时会被压缩；本文关注清单如何进入上下文以及压缩时如何保留任务线索。
> - **作用定位**：理解为什么需要把清单反复写回近期上下文，以及为什么模型消息与界面状态要分开。

- 工具会在会话日志里追加一条类型为 TodoWrite 的事件；这条供界面和回放使用的事件，不会额外作为一条模型消息进入对话历史；界面更新不需要改写已有消息前缀；输入框上方的任务面板靠 Todos 会话投影，根据日志中的 TodoWrite 事件更新界面，并在用户下一轮新提问触发 TurnStart 事件时自动清空旧面板，避免旧清单残留；清空的是面板投影，不是删除历史事件。

> 快速上手：事件日志与会话投影（含 Todos、TurnStart）
> - **一句话本质**：事件日志按顺序记录发生过的事；会话投影是从日志中计算出来、供界面显示的当前状态。
> - **结构化拆解**：TodoWrite 事件记录一次清单写入；Todos 投影根据这些事件生成任务面板；TurnStart 事件表示新一轮提问开始，触发清空旧面板投影；清空投影不等于删除历史事件。
> - **作用定位**：解释模型看到的消息和用户看到的界面如何分离，以及为什么长对话压缩不一定影响前端面板。

- 上下文压缩模块内置固定 Checkpoint 摘要模板，要求把还没做完的任务写进 Pending Jobs 和 CurrentWork 章节，供后续继续；它能帮助保留任务线索，但仍依赖摘要质量，不能当成任务绝不丢失的保证。

> 快速上手：上下文压缩与 Checkpoint 摘要模板
> - **一句话本质**：上下文压缩是把过长对话信息压缩成更短概括的机制；Checkpoint 摘要模板是压缩时使用的固定章节格式。
> - **结构化拆解**：压缩会保留关键信息、丢弃细节；模板要求把未完成任务写入 Pending Jobs 和 CurrentWork 章节；效果取决于摘要质量，不能保证任务绝不丢失。
> - **作用定位**：说明清单在前端和模型侧的不同保留方式，以及长任务中任务线索的局限。

- Plan 模式负责在动手前敲定方案，TodoWrite 用来跟踪方案获批后的执行进度；DeepSeek Plan 模式主要通过部署配置的提示词约束行为，工具仍可调用，不能当成代码层面的权限隔离。

> 快速上手：Plan 模式
> - **一句话本质**：Plan 模式是让 Agent 先产出方案、再执行的工作模式。
> - **结构化拆解**：它把规划阶段与执行阶段分开；本文中规划阶段主要靠部署时设置的提示词约束，工具仍可调用；它不是代码层权限隔离。
> - **作用定位**：说明 TodoWrite 应跟踪执行进度，而不是替代方案规划；也提醒提示词约束的边界。

- 多 Agent 场景：DeepSeek Plan 模式的 Todo 清单属于单个 Agent 会话，SubAgent 各自有自己的清单；各管各的仍可用全量覆写；若一起维护同一张任务板，不能简单照搬，按任务编号更新并配合任务间依赖关系更适合。

> 快速上手：多 Agent 共享任务板 / 按编号更新 / 依赖关系
> - **一句话本质**：共享任务板是多个 Agent 共同维护的同一张任务清单；按编号更新是只改指定任务；依赖关系是任务之间的先后约束。
> - **结构化拆解**：单 Agent 各自清单可用全量覆写；共享时全量覆写易覆盖他人修改，按编号更新可减少冲突；依赖关系用于表达任务先后。
> - **作用定位**：说明全量覆写不是所有 Agent 场景都适用，协作场景要换更新策略。

- Plan 模式仅靠提示词约束、工具仍可调用，如何防止误调用缺少代码层方案。
- TurnStart 清空面板投影后，用户回看上一轮清单的交互细节未展开。
