# 模型之外，谁让AI Agent真正运转？#AI智能体 #AgentHarness #大模型应用 #工具调用 #ai模型分享

# 笔记：底层能力之外，谁让产品真正运转？

## 精华版
同一底层能力装在不同外围系统中，表现会明显不同；外围系统由外部动作接入、信息保存、重复执行和持续校验等模块组成；近期能力提升多来自外围系统改进；评价智能能力时，要同时区分底层能力与外围系统，并注意两者边界正在融合。

## 整体逻辑链条梳理
1. **现象观察**：两个 AI 产品可能使用同一底层能力，但一个只是聊天，另一个能访问文件和终端并连续工作数小时。成立原因：产品体验不只由底层能力决定；衔接：需要找出底层能力之外的部分。
2. **区分底层模型与外围系统**：提出「AI 模型」与「Agentic Harness」的二分。  
   - **AI 模型（首次出现）**  
     - 一句话本质：它是接收输入并生成输出的、经过训练的计算系统。  
     - 结构化拆解：由训练得到的计算结构组成；工作方式是依据输入上下文生成输出；本身不直接读写文件、运行代码或浏览网页。  
     - 作用定位：本文把它视为“底层能力”；掌握它有助于区分模型能力与产品能力，避免把产品差异全部归因于模型。  
   - **Agentic Harness（首次出现）**  
     - 一句话本质：它是包在模型外面、把模型决策转成持续外部行动的系统层。  
     - 结构化拆解：提供外部动作接入；保存和检索信息；运行计划—行动—观察的重复流程；执行权限与行为规则。  
     - 作用定位：本文核心变量，用来解释同一模型放进不同产品后为何表现不同；理解它才能分析工具、记忆、循环和验证。  
   成立原因：模型不能直接操作外部世界，必须由外层系统代执行；衔接：两者合起来构成 AI Agent。
3. **定义 AI Agent**：  
   - **AI Agent（首次出现）**  
     - 一句话本质：它是 AI 模型与 Agentic Harness 组合后的整体。  
     - 结构化拆解：模型负责决定下一步；harness 负责执行动作、回传结果、维持记忆和规则；两者循环协作完成目标。  
     - 作用定位：本文讨论的能力单位；评价一个 agent 时不能只看模型，也要看 harness。  
   成立原因：单独模型只是生成输出，单独 harness 没有决策核心；衔接：要理解 harness 内部，需要继续拆解。
4. **拆解 harness 的三类核心能力**：  
   - **工具（首次出现）**  
     - 一句话本质：工具是模型可调用的外部动作接口。  
     - 结构化拆解：包括文件读写；代码运行与沙箱（沙箱是隔离运行环境，限制代码对系统的影响）；联网获取信息；computer use（模型通过移动光标操作软件界面）；命令行（调用机器上已安装的软件）；MCP（Model Context Protocol，外部服务工具的标准化接入协议，使工具一次开发可接入多个支持它的 harness）。  
     - 作用定位：让模型突破“不能直接操作外部世界”的限制；工具决定模型能做什么、以什么方式做。  
   - **记忆（首次出现）**  
     - 一句话本质：记忆是 harness 对模型上下文和跨会话信息的保存、压缩与检索机制。  
     - 结构化拆解：上下文窗口是模型单次能处理的信息窗口，容量固定且会话结束后清空；AGENTS.md 是放在项目文件夹、每次会话开始加载进上下文的指令文件；压缩是在上下文将满时总结早期内容并剪掉冗余工具输出；搜索是按需检索项目片段，包括 grep 式文本搜索、语义搜索和代码索引。  
     - 作用定位：解决模型工作记忆有限和会话清空的问题；让模型在长任务中保留关键约束并只取所需信息。  
   - **Agentic Loop（首次出现）**  
     - 一句话本质：它是模型与 harness 反复执行“计划—行动—观察”的循环。  
     - 结构化拆解：模型决定下一步；harness 执行动作并返回结果；模型观察结果后继续决策；循环可持续数秒到数小时；现代 harness 在循环中持续验证，包括运行测试、截图检查、启动独立 reviewer 模型检查结果。  
     - 作用定位：支撑长时间任务；验证让模型边做边查，减少偏离目标。  
   成立原因：工具扩展行动、记忆维持信息、循环维持连续执行；衔接：三者共同运行时，AI 能做的事开始明显超出单独模型。
5. **工具机制成立的原因**：模型缺少外部动作能力，harness 通过标准化接口把模型请求转成具体操作并返回结果。衔接：行动产生结果后，需要记忆与循环接住。
6. **记忆机制成立的原因**：模型上下文有限且会话会清空，harness 通过项目指令文件、压缩和按需搜索维持关键信息。衔接：信息保留后，模型才能在循环中持续决策。
7. **循环与验证机制成立的原因**：长任务需要反复计划、执行、观察；持续测试、截图和 reviewer 模型提供反馈，使模型能长时间运行而不轻易偏离目标。衔接：这解释了产品能力差异为何常来自 harness。
8. **为什么这个区分重要**：近期能力增益多来自 harness 的工具、记忆和循环改进；评价“AI 是否擅长某事”时，要同时问用哪个模型、配哪个 harness；模型与 harness 的边界还在流动。  
9. **结论回收**：模型继续变强，harness 也关键；产品表现是两者共同结果。

## 一句话结论
（对应链条第 9 环：结论回收）同一底层模型的产品表现差异，主要取决于包在模型外面的 Agentic Harness，因此评价 AI 能力要同时看模型与 harness。

## 核心要点
（对应链条第 2—8 环：区分、组件、意义）
1. 同模型在不同产品中表现不同，差异常来自 Agentic Harness。
2. AI Agent 由 AI 模型和 Agentic Harness 组成。
3. Harness 核心包括工具、记忆和 Agentic Loop。
4. 工具让模型能读写文件、运行代码、联网、操作界面和接入外部服务。
5. 记忆通过上下文窗口、AGENTS.md、压缩和搜索维持长任务信息。
6. 循环与持续验证支撑长时间行动；评价 AI 要同时问用哪个模型和哪个 harness。

## 关键细节
（对应链条第 5—7 环：工具、记忆、循环与验证的具体机制）
- 同一模型可只做基础聊天，也可放入带文件与终端访问权的开发者工具中，连续工作数小时。
- 视频提到：多数评测中，顶级实验室之间的基准差距已缩小到几个点以内。
- Harness 的工具包括：文件读写、代码运行、沙箱、联网、computer use、命令行、MCP。
- MCP 让为它构建的工具可接入任何支持该协议的 harness，不必每次重写。
- 记忆方面：上下文窗口容量固定，会话结束会清空；AGENTS.md 在每次会话开始时加载；上下文将满时进行压缩，保留重要内容并剪掉冗余工具输出；搜索可包括 grep 式文本搜索、语义搜索、代码索引。
- 循环方面：模型计划，harness 执行，模型观察结果，再重复；循环可持续数秒到数小时。
- 验证方面：模型可运行测试、截图检查，甚至启动独立 reviewer 模型检查结果。
- 视频指出：模型可能在一个 harness 中表现很好，在另一个 harness 中卡住。
- 模型与 harness 的边界在流动：长程规划、自我验证等能力开始被训练进模型；长任务一致性等模型行为也越来越多受 harness 约定和项目文件影响。

## 原文文案

You might have noticed that two AI products can feel completely different, even when they're running the same underlying model. Like how the same model could be a basic back-and-forth chatbot, but if you put it inside a developer tool with access to files and a terminal, it can suddenly work for hours on a software task. So, so what accounts for the difference? Well, it comes down to the AI model and the agentic harness, and let's start with the AI model, because what that is is pretty simple. We all know what these AI models are, things like ChatGPT or maybe Claude. So, when we talk about a model, we really mean the actual artificial neural network. And what those models can't really do on their own is reach out into the world. They can't open a file or run a piece of code natively. They can't really browse the web either. So, on their own, these AI models are essentially, well, a brain in a jar. They're capable, but they're trapped. They're trapped in that jar. Now, benchmark gaps between the top labs have narrowed to within a few points of each other on most evals. So, when one AI product clearly outperforms another, the brain itself, by which I mean the AI model, usually isn't the explanation. It's what's wrapped around the brain. And that wrapping has a name. When we take a model and we wrap it, we are calling this thing that wraps it the agentic harness. And then, if we think of an AI agent overall, that encompasses both of these things. So, essentially, an AI agent consists of the AI model and the agentic harness. That's the tools the model uses, the way it remembers things, the loop that it keeps running, the rules about what it's allowed to do. All of that stuff lives inside the agentic harness. So, let's get inside that harness. And what's inside is essentially three components. We've got tools, we've got memory and we've got the agentic loop. Let's take a look at these one at a time. We'll start with tools. So, through tools, the model can do things out in the world. For example, one of the things it can do is it has access to files so it can read and write to them. Another thing we can do with tools is run code. And that code might run in a sandbox as well. We can go and get information on the internet. And we can also often actually drive a computer screen itself. This is called computer use. And here the model can move a cursor around and operate any software similar to the way that a person would do it. Now, many of these capabilities are actually built into the harness directly. For anything else already on the machine, well, a harness usually gives the model access to the command line so it can just run whatever software is already installed, which is really the same way that a developer would do it. And then, for connecting to external services that don't live on the machine—so maybe a corporate database or a third-party app—there's a standard called MCP, Model Context Protocol. And a tool built for MCP can plug into any harness that supports it without being rebuilt each time. That's tools. What about memory? Well, models have a fixed context window, which is basically their working memory. And once the conversation ends, that working memory is wiped clean, but the harness can help persist things. For example, it can persist instruction files, so things like an AGENTS.md file, which sits in a project folder and gets loaded into the model's context at the start of every session. That's how the model knows the codebase conventions or what libraries to use. Now within a session, when the context window starts filling up, the harness runs another process where it compacts that context window. So it summarizes what happened earlier. So the important parts stay around, but stuff like redundant tool outputs, all that stuff kind of gets pruned out. And then rather than dumping an entire codebase into the model's context all at once, the harness lets the model perform a search. So we can search the project sometimes with grep-like text search, sometimes with semantic search or code indexes, and then just kind of pull only the pieces it needs. That's memory. And then there is the agentic loop. Now this is where the harness and the model work together to achieve a goal. So the model decides on a next step to achieve that goal. That's the plan stage. And then the harness takes that plan and actually performs an action on it. When that action is performed, we get some results. The model observes those results, and then the loop repeats around and around, sometimes just for a few seconds, sometimes for hours. And in addition to this cycle, modern harnesses run verification continuously all the way through the loop. The model runs tests as it goes. Maybe it takes screenshots of what it's built and sometimes even spins up a separate model to act as a reviewer. So verification is pretty cool, running these tests and checking the outputs and taking a peek at screenshots. And a model that double-checks itself might run a lot longer without going off the rails. So that's tools, memory and the agentic loop. Once a harness has all three of these running together, the kinds of things AI can actually do start looking very different from anything an AI model can do on its own. So I think we should also ask, why should we care about this distinction, AI model and agentic harness? Well, because once we can see the model and the harness as separate things, I think a lot of what's been going on in AI starts to make a bit more sense. Because most of the capability gains we've seen lately, they've come actually from the harness getting better, by which I mean better tools and memory handling and smarter agentic loops with verification. And of course, with every new version, the models have improved as well. So when somebody asks, is AI good at something, like is AI good at writing code or is AI good as a customer support chatbot? I think the more useful version of that question is to better define what we mean by AI. And specifically, we mean two things. We mean which AI model are we going to use in this scenario. But also, if this is an agent, we need to ask which harness are we going to use with that AI model as well, because the model can be brilliant in one harness and get stuck in another. And the line between these two things is also a bit fluid because capabilities that used to live entirely in the harness, like long-horizon planning or self-verification, they're starting to be trained directly into the models and things that used to be model behavior, like consistency over a long task, are increasingly shaped by harness conventions and project files, which brings us back to that brain in a jar. The brain itself, the AI model, continues to get smarter. There's no doubt about that. But you know what? It's not just the model getting smarter. It's not just the brain. It's also the jar, the agentic harness.
