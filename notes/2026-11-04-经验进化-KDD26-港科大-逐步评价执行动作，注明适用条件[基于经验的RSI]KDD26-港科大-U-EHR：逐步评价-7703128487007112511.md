# 经验进化-KDD26-港科大-逐步评价执行动作，注明适用条件 [基于经验的RSI] KDD26-港科大-U-EHR：逐步评价执行动作，给有效做法注明适用条件，让病历查询少走弯路
U-EHR: A Self-Evolving EHR Agent with Step-Level Credit Assignment and UCB-Guided Memory Retrieval 
1. U-EHR 由香港科技大学、香港科技大学（广州）与广州中医药大学团队提出，发表于 KDD 2026。它让电子病历智能体在模型参数保持不变的情况下，跨任务积累和使用自己的操作经验。
2. 最终答案的成败会掩盖中间动作的差别。系统在任务完成后，分别评价每一步与问题的相关性、对任务的推进程度，以及工具使用和结果解释的正确性，从中筛选值得复用的做法和错误教训。
3. 每条记忆对应一次任务，保留带分数的执行记录。正向经验写明有效做法、原因和适用条件；负向经验写明错误、原因、替代做法与严重程度。失败任务还会生成整体反思。
4. 新任务默认检索 3 条正向记忆与 2 条负向记忆。排序结合任务语义相似度、原执行质量和后续使用效果，并通过上置信界原则给较少使用的条目探索加分。一次任务使用的多条记忆共享同一个成败反馈，记忆贡献的评价仍较粗。
5. 英文评测覆盖六类病历任务。在 Qwen3-32B 上，平均 F1 从已测基线最高的 0.1479 提高到 0.1938，相对提高约 31%。四种骨干的平均结果均领先，但提升幅度不同，Grok-4-fast 约为 0.3%，部分单项任务落后于基线。
6. 逐步评分对效果贡献较大，移除后平均 F1 降至 0.1403。负面经验的作用随任务变化，删去错误提醒后的平均分为 0.1955，略高于完整系统。怎样根据任务需要调整错误提醒，是后续研究问题。
7. 论文案例中，记忆引导智能体优先查询住院、出院与影像记录，并避免对没有时间字段的表重复过滤。工具交互和输入 token 均有节省，完整成本评测仍需统一计入步骤评分、经验抽取和执行过程的输入输出及延迟。
8. ExpRAG 利用相似患者的临床内容，ActiveMedAgent 学习病例内的证据采集与停止，U-EHR 积累跨病例的数据库操作经验。与批量归纳技能目录的 Trace2Skill 相比，本篇在每次任务后更新记忆，并调整后续检索。#全民进入购物听劝时代 #vibe知识大赏

## 一句话结论
U-EHR 在基础模型参数不变的前提下，通过任务后逐步评分、带适用条件的正负经验记忆和 UCB 检索，让电子病历智能体跨任务积累并复用操作经验。

## 核心要点
- 系统在任务结束后回看完整执行记录，逐步评分并抽取可复用做法和错误教训，再写入经验库。
- 每步评分综合动作与问题相关性、任务推进程度、工具使用与结果解释正确性，三项各 0—2 分，相加后除以 6。
- 正向经验写明有效做法、原因和适用条件；负向经验写明错误、原因、替代做法和严重程度，失败任务还会生成整体反思。
- 新任务默认检索 3 条正向记忆和 2 条负向记忆，排序结合语义相似度、原执行质量、后续使用效果，并用 UCB 给较少使用条目探索加分。
- 在英文基准 Qwen3-32B 上，平均 F1 从已测基线最高的 0.1479 提高到 0.1938，相对提高约 31%；四种骨干平均领先，但提升幅度不同。
- 逐步评分对效果贡献较大，移除后平均 F1 降至 0.1403；负面经验作用随任务变化，删去错误提醒后平均分为 0.1955，略高于完整系统。

## 关键细节
- 论文发表于 KDD 2026，作者团队来自香港科技大学、香港科技大学（广州）与广州中医药大学。
- 每条记忆对应一次任务，保留带分数的执行记录，也保留整理后的经验。
- 三项合计至少 5 分的步骤用于抽取正向经验，至多 1 分的步骤用于抽取错误教训，中间步骤暂时不抽取。
- 消融结果：移除逐步评分后 F1 为 0.1403；检索只按语义相似度时 F1 为 0.165；删去错误提醒后 F1 为 0.1955。
- 案例中，基线 ReAct 大量扫描表结构并反复查询缺少时间字段的表，最终用完 100 步仍未满足编码要求；U-EHR 优先查询住院、出院与影像记录，在 13 步内给出正确编码。
- 成本方面，整断任务输入 token 比 ReAct 少约 75%，微生物任务少约 9%；完整成本仍需统一计入步骤评分、经验抽取、执行输入输出和延迟。
- 中文评测采用新建病例基准，含中国医院病例和本地诊断编码，测试集有 100 名患者；完整方法在两种骨干上领先，小模型则低于一种使用上下文摘要的已有方法。

## 原文没有讲清的问题
- 失败任务中的高分步骤能否进一步转为可检索的正向经验，文字稿称论文没有说明。
- 检索排序去掉质量和探索后，无法单独衡量 UCB 探索加分的贡献。
- 如何根据任务需要在执行前判断应给多少错误提醒，而不是事后按任务类型推测。
- 完整成本如何统一计入步骤评分、经验抽取、执行过程的输入输出和延迟。
- 步骤评分与独立人工评价的一致性未报告；实际使用时任务成功反馈从何而来也需要可信机制。
- 英文经验库能否直接迁移到中文任务，尚缺冻结英文经验库后单独测试中文任务的验证。
- 旧经验过时、相似条目重复、错误提醒互相冲突等长期维护策略未详细展开。
- 中文评测中经过时间修正的文书，在预测时点之前实际能获得哪些信息，仍需按内容审计。
